# The component roster: what this system draws, what the app builds, and the
# three places those deliberately differ.
#
# Format:  <area>/<Name>  <both|design-only|code-only>  [reason, required unless "both"]
#
# `both` means components/<area>/<Name>.jsx here AND
# android/…/ui/components/<area>/<Name>.kt in the app. The app's
# `ComponentRosterTest` reads a vendored copy of this file and fails on anything
# it does not expect — a component designed and never built, or built and never
# designed, or renamed on one side.
#
# WHY IT LIVES HERE. Same reason as strings.txt: a roster kept on the code's side
# can only check the code against itself. Moved 2026-08-09.
#
# THE POINT OF THE TWO EXCEPTION KINDS. A roster that only listed matches would
# have to be edited into a lie the first time a legitimate asymmetry appeared,
# and then it would stop being read. Naming them costs one line each and keeps
# the check honest — an unexplained absence is a failure, an explained one is a
# decision.
